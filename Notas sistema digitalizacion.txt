Exacto, todo se comprime en un solo export_YYYYMMDD_HHMMSS.tar.gz que contiene:
- db.sql → la base de datos completa
- minio_data.tar.gz → los archivos PDF subidos
- docker-compose.yml → configuración de servicios
- .env.example (o el .env sin secrets sensibles)
Para restaurar solo necesitas ese .tar.gz.
Plan detallado:
export.sh
1. Crear carpeta temporal export_$(date +%Y%m%d_%H%M%S)/
2. docker-compose exec -T postgres pg_dump -U admin digitalizacion > temp/db.sql
3. docker run --rm -v <volumen_minio>:/data -v $PWD/temp:/backup alpine tar czf /backup/minio_data.tar.gz -C /data .
4. Copiar docker-compose.yml a temp/
5. tar czf temp.tar.gz temp/
6. Eliminar temp/
restore.sh <archivo.tar.gz>
1. Extraer el tar.gz
2. Asegurarse que los contenedores postgres y minio estén corriendo
3. cat db.sql | docker-compose exec -T postgres psql -U admin digitalizacion
4. docker run --rm -v <volumen_minio>:/data -v $PWD:/backup alpine tar xzf /backup/minio_data.tar.gz -C /data
5. docker-compose restart backend
6. Limpiar archivos extraídos
Consulta sobre el nombre del volumen
Los volúmenes se nombran automáticamente como {nombre_carpeta_proyecto}_{nombre_volumen}. En tu caso sería algo como sistemadigitalizaciondearchivos_postgres_data y sistemadigitalizaciondearchivos_minio_data.
Para confirmar, el script detectará automáticamente el nombre real con docker volume ls y docker-compose ps -q. ¿Te parece bien?
